## 三、★ 抠图口径（用户当轮明确改口，务必先读）

长期规则是**「抠图一律 rembg」**，但本轮实测后**用户当场改口**：

> 用户原话：「**抠好了，就直接替换进去试试看**」

原因（实测数据）：这批素材**本身已经是抠好的** —— 27 张全部自带 alpha（背景 `α=0`、牌体 `α=255`，
`0<α<255` 的像素仅 `0.0~0.4%` ⇒ 近乎二值硬边）。而 rembg 重抠会**把它们切坏**：

| 素材 | 自带 alpha 牌体 | rembg 重抠后 | IoU | 结论 |
|---|---|---|---|---|
| 万子 1_wan | 74.8 万 px | 77.4 万 px | 0.966 | 尚可 |
| 条子 2_tiao | 289.3 万 px | **23.0 万 px** | **0.080** | 🔴 只剩 8% |
| 筒子 1_tong | 164.8 万 px | 166.8 万 / 72.3 万 px | 0.982 / 0.439 | 不稳定 |

根因：**条 / 筒是白瓷面，其透明区底下的 RGB 也是白的**（`255,255,255`）⇒ 压白底后白牌与白底不可分，
**只有 alpha 通道知道牌在哪**，任何分割模型都救不回来。

⇒ **本轮管线 `tools/r61-ceramic.py` 全程不调用 rembg**，直接以 `alpha > 8` 定 bbox → 内切 224×298。

## 四、与「当前在用」三处的关系

本套装是**归档/命名层**；工程实际读取的是下面三处（同源）：

| 代号 | 位置 | 内容 |
|---|---|---|
| A 源图库（设计母版，不进包） | `<root>/assets/_src/game-play/tiles/<suit>/<中文数字><花色>.png` | 裁切后**全尺寸 RGBA 母版** 27 张 |
| B 成品库（工程版 @2x） | `<root>/assets/game-play/tiles/<suit>/<中文数字><花色>.png` | **224×298** 27 张 |
| C 运行期 bundle | `game-5-cocos/assets/bundles/game/tiles/<suit>/<suit><n>.png` | **224×298** + 同名 `.meta`（**UUID 必须不变**）+ `_dead.png` 灰阶被压版 |

> ⚠️ 改牌面**只覆盖 png，绝不碰 `.meta`** —— 否则 uuid 断裂、工程引用全失效。
> 灰阶被压版由 `tools/r45c-gray-tiles.py` 重烘（`scale=0.75` → 168×224）。

## 五、迭代入口

