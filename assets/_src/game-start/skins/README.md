## 二、方案 B 的缺陷（上架前必须先修）

| 缺陷 | 实测 | 后果 |
|---|---|---|
| **桌面左右被画幅裁切** | 桌体横向 span 满画幅，毡面 mask 左右被切 | 桌面不是完整正方形，无法直接当主玩页地基 |
| **非严格俯视** | 毡面上下宽度差 **3.0%**（列向边缘斜率收敛） | 引擎平铺的牌会与桌面透视打架 |
| 骰盘椭圆度 | 长宽比 1.29（另两案 ≈1.02） | 圆盘明显是椭圆，聚焦运镜会暴露 |

**修补两条路**（择一即可）：
1. **重出**（推荐）：提示词已含"exactly SQUARE table / all four edges fully inside the frame"约束（见 `docs-verify/game-5/game-start/` 的 `game-start-table-v2` 提示词），重跑一次即可拿到合规正方形桌；再走「边缘直线拟合 → 手工单应校正 → 毡面中心裁切」三步。
2. **修补**：从当前原图做单应校正 + 外沿补绘（左右各补 30~50px 木纹）—— 成本高于重出，不建议。

> 目录内 `table_750_UNUSABLE.jpg` / `table_1024_UNUSABLE.jpg` 保留的是**当时那份不合格裁切**，仅作对照，不要投产。

## 三、皮肤接入规范（上架时照此做）

1. **命名**：`table_skin_<id>.jpg`（如 `table_skin_a.jpg`），750×750，落点与默认皮肤一致（`x=0, y=292`）。
2. **体积**：单皮肤 ≤ 140 KB（与默认皮肤同量级）。主包只内置默认皮肤，其余皮肤走**分包或云端下载**（主包 ≤ 4096 KB 的纪律）。
3. **几何一致性**：新皮肤的**骰盘圆心/直径**必须重新实测并记录 —— 运镜锚点用的是骰盘圆心而非桌面几何中心，各皮肤不一定同位置。实测脚本口径见 `refine_final.py` 的 `tray_metrics()`。
4. **正交度准入线**：新皮肤上线前必须实测正交度，**≤ 1.0 px/100px** 才可投产（默认皮肤 0.08，方案 A 6.62 属可接受上限）。
