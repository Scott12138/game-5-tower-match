## 二·补三、开局掷骰 · 点数与赠礼（第 11 轮落地 → 第 12 轮本局限定护栏 → **第 13 轮映射表定稿微调 + 复活**）

| 项 | 值 |
|---|---|
| 点数生成 | **真随机**：`crypto.getRandomValues` + 拒绝采样（丢弃 ≥ 2³²−4 的尾部块，**彻底消除取模偏置**）；两颗骰子各 1–6 |

## 三、定稿工艺（本批踩到的坑，务必照做）

1. **AI 出的"严格俯视"都带透视** → 判据：毡面左右边缘**斜率收敛差**（px/100px，0 = 真正交）。
   - 通用惯例：**不要盲用单应校正**。方案 C 用自动四角检测校正后反而变差（3.87→7.45）。
   - 本轮改用「**边缘直线拟合求四角**」做手工校正，方案 C **4.46 → 0.08**（改善 99%）。
2. **裁切中心必须用「毡面中心」**，不能用「桌体框中心」 —— 桌框外扩量若某一边被暗部污染（本轮左侧测成 1px，其他三边 52/53/63），中心会被带偏 27px，导致桌面在画布里偏心（毡面留白 左69/右99）。修正：**多行采样取中位数 + 异常小值（< 其他三边中位数 30%）用中位数替代**。
3. **骰子走矢量自绘**（AI 画不准点数与视角：要 5 出 1、要 85° 俯视给 45° 斜视）。矢量绘制 + 预乘 alpha 缩放 + 低 alpha 像素 RGB 归零 = 边缘干净。
4. **骰子绝不能画进桌图** —— 碰撞动画要求它能单独运动，必须独立图层。
5. **判据别写成绝对阈值**：本批两次误报都源于此 —— ① 骨白骰本体 lum≈0.96，落进"近白"判据 → 误报白毛边；② alpha 已归一化到 0~1 却仍用 0~255 阈值比较 → 读数全 0；③ 六面核验时用 `白晕 == 0` 判"边缘干净" → 误报六面**全部**不合格（该 975 像素实为顶面左上高光边，属设计元素）。
   → **正确做法：以已确认的基准版本为对照逐指标比对**，即 `face_*.png` 的三项边缘指标必须与 `face_4`（= 已确认 dice.png）完全相同。本批六面实测全部等同。
6. **多面骰的"风格统一"是可断言的**：几何参数（顶面边长 / 圆角 / 侧壁厚 / 面板内缩 / 点径 / 光照方向）全部锁定为常量，只让点阵变化 → 六面 **bbox 一致、内容占比一致、母版尺寸一致、边缘指标一致**。任何一面偏离即说明参数被意外改动。
7. **★ "物件进容器"的尺寸校核必须扫全程极值，不能用静止位代替**（第 8 轮踩到）：第 7 轮我按"落定位置"算出 56 的最远点 77.4 ≤ 81，看着还剩 3.6 余量；第 8 轮做碰撞动画时对 **1 ms 步长扫全时段**，才发现**回弹过冲**（t≈210ms）会到 **81.6 > 81**。
   → 规矩：凡"A 放进 B"的尺寸判定，都要先写清楚**A 在 B 里的运动包络**（静止 / 摆动 / 过冲 / 弹跳），再对包络求极值；只算静止位一定漏。
8. **首帧要"干净"就得让进场物真的在视野外**：骰子起点按 4.27× 边长时，边缘会露出一条白边（视野半宽 178.6，骰子内缘已进画面）；改成 **5.0× 边长** 才是真正的"画外起飞"。
9. **★ 挤压的各向异性拉伸必须计入包络**（第 9 轮踩到）：挤压是"**沿对撞轴压、垂直方向伸**"，所以骰子的外接圆半径要乘 `max(sx, sy)`（含 `STRETCH` 项）。上一版只算了"离地放大"，于是 **C 方案贴壁迎头相撞 + 切向挤压 → 径向伸出** 被整整漏判（解析值 82.3 > 81）。
   → 修法两处缺一不可：① 包络公式补 `aniso` 因子 `max(1 - squashAmp·sq, 1 + STRETCH·sq)`；② 撞点半径**主动内收**（撞压 → 离壁），并**按内收后的半径反解贴合角**（否则单纯内收会让两骰穿插）。
   → 通用规矩：**"擦着边"的碰撞要先想清楚"撞的那一下往哪个方向伸"**，再看看那个方向是不是正好朝外。
10. **硬质骰的挤压幅度要小**（第 9 轮手感修正）：真麻将骰是硬质密胺，撞击几乎不变形。上一版 `squashAmp = 0.34`（压 34%）放出来是"橡皮糖"，一眼假 → 收到 **0.15 左右**（压 15% / 伸 12%），既有"撞了一下"的顿感又不软塌。
11. **★ 自转必须早于淡出归零**（第 11 轮抓到）：`realignFace()` 是拿"自转终止时刻"的朝向反解偏移量的 —— 若自转拖到 `rollEnd(1150ms)` 才停，而骰子 `fadeOut(1020ms)` 就开始淡出，**玩家在能看清的时候看到的点数不是最终点数**。实测：目标 `3|5`，但 t=1000/1020 时显示 `6|3`，直到 1100ms 才变成 `3|5`。修法：新增 `CFG.T.spinEnd = 950`，三套方案的 `spin()` 一并收敛到它（位置仍归零于 `rollEnd`）—— 于是 **t≥900ms 面已锁定**，玩家有 ~250ms 的清晰窗口。**凡是"随机结果要展示给人看"的动画，都要检查"结果确定时刻"是否早于"退场开始时刻"。**
12. **★ LCG 不能直接吃原始种子**（第 11 轮抓到）：`makeRng(seed)` 首输出与种子线性相关，实测种子 100/101、102/103… **成对给出完全相同的点数**，而且单调递增。修法：先把种子过一遍 **murmur 型 finalizer**（`scramble()`：异或魔数 → 乘 0x85EBCA6B / 0xC2B2AE35 → 右移混合）再进 LCG，扩散后 100→11 / 101→15 / 102→65 全不相同。**任何"给种子就能复现"的功能，都要专门测"相邻种子是否被打散"。**
13. **★ `<audio>.play()` 有启动延迟，必须补偿**（第 11 轮抓到）：不做补偿时音频**稳定滞后画面约 55ms**（实测 −53 / −61ms，不是抖动而是恒定偏移），足以让"碰撞音"拖在画面前面之后。修法：起播时把音频位置设为 `(t + lead)/1000`，`lead = 55ms`；播放中每帧监控，偏差 > 45ms 才硬校（避免抖动/爆音）。修正后实测偏差 **−2 / 0 ms**。
14. **base64 内嵌资源的路径重写要先"抠块"**（第 11 轮踩到）：base64 字母表含 `/`，理论上可能凑出 `assets/` 子串而被归档脚本误改。`make_archive.py` 先正则把 `src="data:..."` 整块取出占位，替换完路径再原样还原 —— 归档后 `src="assets/..."` 残留必须为 **0**。
15. **★ "本局限定发放"的道具，绝不能用"累计台账"实现**（第 12 轮定稿）：反刷护栏的正确结构是 **一个可关闭的当局容器**（`RUN = {open, items, used, voided}`）+ **三个动作**（开 / 用 / 结），而不是往一个跨局数组里累加。要点：
    - ① **唯一权威来源**：当局容器是道具存在与否的唯一依据；历史流水只记"已作废的局"，**永不参与发放判定**。
    - ② **所有"离开本局"的路径都要作废**：结算、提前退出、**重掷/换关**都必须走同一个 `endRun()`，否则会出现"漏掉的出口"把道具偷偷带走。
    - ③ **作废后必须拒绝复活**：关闭后调 `useItem` 要明确返回失败（实测 `本局已结束，道具已作废`），而不是静默成功。
    - ④ **面板要能自证**：直接显示"可继承 / 累计持有 = 0"，让"不累计"这件事可见可验。
    - ⑤ 验收时必须**逐路径真点**（结算 / 退出 / 重进 / 池空 / 结束后再用），不能只测一条 happy path。
16. **★ "自动生效"类道具不要塞进道具池**（第 13 轮定稿）：「复活」这类**不由玩家主动点击**、而是在特定时机（本局失败）**自动生效**的道具，若塞进道具池会带来两个问题：① 道具栏里出现一个"点不出效果"的按钮（它的使用时机不在玩家手里）；② 面板语义错乱（标着"可用"却不给点）。
    - 正确做法：**独立字段 + 独立剩余量**（`revive / reviveUsed / reviveVoided`，`reviveLeft()` = 三者之差），面板**单独一行**展示并注明"自动 · 不入道具栏"。
    - 但**作废与继承规则必须和道具池完全同规**：本局限定、未用即作废、不累计、不跨局 —— 否则它会变成一条绕过护栏的暗渠。
    - 面板还要能区分"**用尽**"与"**本来就没有**"：由 `used.length` 决定文案，不能一律写"已用尽"（第 13 轮抓到并修正）。

17. **★ 页面定稿入库要"同源生成"，不要"另存副本"**（第 14 轮）：把页面验收定稿时，最容易顺手把工作稿复制成 `*-定稿.html` —— 但那样会诞生**两份各自漂移**的文件，下次改功能必然只改其中一份。正确做法：**定稿版与留痕版都由同一份工作稿用脚本生成**（本轮 `make_final.py`（定稿）/ `make_archive.py`（留痕）**共用同一套路径重写规则**，差异只在标识文案），并在台账写明"**改功能请改工作稿，再跑脚本重新生成**"。
    - 附带纪律：两条脚本都必须**先把 `src="data:..."` 的 base64 块抠出占位再替换路径**（base64 字母表含 `/`，可能凑出 `assets/` 子串被误改）；生成后**必须复验 `src="assets/..."` 残留 = 0**。
    - 顺带：**未选中候选也要入库留档**（第 14 轮用户明示"以备不时之需"）—— 选定项进正式区、其余进 `candidates/` 并标注"**不进主包**"，别让储备悄悄吃掉主包预算。
