## 三、筛选口径（无"耳朵"条件下的定量排序）

**排序口径：碰撞脉冲数 ↓ → 低频占比 ↑**

| 指标 | 含义 |
|---|---|
| **碰撞脉冲数** | 包络过阈值的独立峰数 = 盘内弹跳次数（越多越像"哗啦滚动"） |
| **低频占比** | < 1 kHz 能量占比 —— **越低 = 高频越丰富 = 越"脆"**（硬质密胺骰）；越高越闷 |
| **ZCR** | 过零率，越高越"沙" |
| 起音 | 首个显著峰的时刻（对齐"起转"用） |

## 四、为什么是 #3（选定理由 · 与动画节拍天然对齐）

| 音频（实测） | 动画（B「追尾」） | 偏差 |
|---|---|---|
| 起音 / 最强撞击 **80 ms** | **70 ms** 起转（被驱动甩出） | 10 ms |
| 主脉冲 **310 ms** | **300 ms** 追尾碰撞 | 10 ms |
| 自然衰减（630 ms 后） | 惯性滑行减速 | — |

- **未裁切、未变速**：与动画**同一时基 t=0** 起播即可（#3 有效段仅 80–630 ms，其后 1420 ms 是静音，衰减尾恰好对上"滑行减速"）。
- 嵌入方式：分镜页 / 定稿页的 `#sfx` 走 **base64 内嵌**（预览沙箱 / 双击本地文件都能播）。
- 播放控制与动画**同起同停**；`<audio>.play()` 有 ~55 ms 启动延迟，已在起播位置补偿（补偿前稳定滞后 −55 ms，补偿后实测偏差 **−2 / 0 ms**）。
- **不做按钮层、不做电机层**（用户第 11 轮拍板）—— 免费可商用源里没有"电动麻将机整机"录音，用户明确不要补。

## 五、工程接入建议

1. **主包纪律**：只把 `sfx-roll-dice.mp3`（48 KB）打进主包；`candidates/` 是储备，**不要打包**。
2. 微信小游戏用 `wx.createInnerAudioContext()` 加载本地音频文件即可；音量建议 `0.85`（与设计稿内嵌时一致）。
3. 若后续要做"**按下按钮**"的手感，可再评估 `麻雀牌.mp3`（0.31 s 单击）作候选 —— 但**当前口径是不加**。
4. 换音效时**必须复算"音频主脉冲 vs 动画追尾碰撞(300 ms)"的对齐偏移**，别直接替换文件。
