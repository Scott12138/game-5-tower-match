## ⚠️ 「扫码报运行环境加载失败」的判据（第 36 轮新增）

出码脚本会打印 `✔ preview` 并给出**解码正常**的二维码 —— 但这**不代表包传上去了**。
真实链路是两步：本地编译 → **上传到 `servicewechat.com`** → 服务端出码；
**上传失败完全静默**（所有常规检查都是绿灯）。

**唯一可靠判据 = IDE 日志 `task type:upload exec error` 的「增量」**，已固化进脚本的 `[8/7]` 段：

```
✅ 日志无新增上传错误（基线 18 → 现在 18）—— 上传通道正常
❌ 检出 N 条 task type:upload exec error —— 本次预览包**没传上去**   （脚本会 exit 3）
```

日志位置：`~/Library/Application Support/微信开发者工具/*/WeappLog/logs/*.log`

**若 `[8/7]` 报错**，四条修法任选：
1. 给 ClashX 规则集加 `DOMAIN-SUFFIX,servicewechat.com,DIRECT`（推荐，一劳永逸）；
2. 微信开发者工具 → 设置 → 代理 → 改「不使用任何代理」；
3. 临时关掉系统代理后出码；
4. 直接用 `bash tools/wechat-preview-safe.sh`（自动临时绕代理，**`trap` 保证任何退出路径都恢复**）。

> ⚠️ 改完代理配置**务必复查 7890 端口在不在听**（热重载可能让 `port`/`mixed-port` 归零 ⇒ 整机断网），
> 坏了就重启 ClashX 恢复。详见 `70-第36轮-扫码无法进入-排查与解决.html`。
