★ A8-① 牌堆的「位置」从哪来？（本轮最关键）
现状：3 层 × 4×3 网格、层偏移恒定 (46,46)、36 张全部 0° 正放 —— 层与层只差一个固定偏移，一眼就能看出是同一张网格复制三次，这就是「显得很假」的根因。
《羊了个羊》的做法是：卡位是人工设计好的图案、每天换一次，程序只负责"把牌洗进卡位"； 它的"乱"来自图案本身不规则，不是来自随机。
隔壁 game-4 走的是另一条路：程序化"层片模型"（每层一片随机散布、层心独立漂移），已跑通且验证过。
三选一：甲 图案卡位表（对齐羊了个羊 · 难度可控、最像 · 但需逐关设计图案）； 乙 层片模型（对齐 game-4 · 零人工、30 关不重样 · 难度不可控）； 丙 图案骨架 + 程序抖动（图案定"哪里密哪里疏"，程序在骨架内抖 · 兼顾两者，推荐）。
对比图：55-牌堆散落方案-对比板.png（面板 ③ = 乙 · 面板 ④ = 甲）
★ A8-② 要不要放开「同层不重叠」这条硬约束？
现在页内有一条硬约束「同层步进 ≥ 牌尺寸 ⇒ 同层不重叠」，好处是同层的每一张都看得清。
但它也正是"轮廓只能是方正网格"的原因 —— 让牌堆紧凑成一坨（有"堆"感）必须靠层内瓦叠： 行步进从 150 压到 ≈64（= 牌高 × 0.5），行与行互压一半。game-4 用的就是 CELL_H_RATIO_STACK 0.48。
三选一：保持不重叠（读牌最清楚，轮廓偏方正）／ 放开为"同层可瓦叠"（有堆感；⚠ 需新定义"同层里谁压谁"—— 建议按行号：靠下（近）的压靠上（远）的，与 game-4 一致）／ 完全放开（任意重叠，最像随手撒的，⚠ 可点判定会变得很碎）。
★ A8-③ 随机朝向开不开？（现在 [0]，一张都不歪）
真实牌堆里"大半摆得挺正、少数歪着"。game-4 的做法是 四向基础朝向 [0,90,180,270] + 偏斜档位： 0°:55 / 5°:12 / 10°:9 / 16°:7 / 24°:6 / 33°:6 / 45°:5（权重）。 它的注释里留了一条重要权衡：不直接 0~360 自由随机 —— 牌面全乱转之后玩家第一眼分辨不出"这是几万几条"，而本作核心操作恰恰是"扫一眼找到能凑的那张"。
⚠ 代价：大角度牌的占位是 1.65 倍面积（game-4 实测），会同时压掉网格容量与开局可点牌数。
四选一：不开（读牌最快）／只横竖（0/90/180/270）／ 横竖 + 小角度 5~25°（"随手一放"的典型区间，推荐）／按 game-4 全档位（含 33/45°）。
★ A9 发牌怎么保证"能清完"？✅ 第 31 轮已解决
用户第 31 轮拍板：「上限改成 138，每关初始的时候要设置成能消完」→ 取方案甲 · 逆向构造（而非乙 / 丙），落地为 满清可解：
· greedy_peel(open_first=3G) 贪心可点剥离 → 合法消除序列 → fill_by_triples() 按连续 3 张同种填充；
· 三套独立实现互证（Python 构造 / Python 复算 / 浏览器内 JS 独立复算），另有断言校验「每连续 3 张同种」；
· 实测 30/30 关满清可解 ✅（2877 张全部可清空）。
—— 以下是第 29 轮的原始问题与三选项（已作废，仅留痕）——
精确算出来的硬结论（旧口径）：12 档最多清 50% · 36 档 67% · 96 档 91%， 三档都不可满清 —— 剩余的张无论怎么打都消不掉。
根因：发牌是从 27 种里逐个独立随机抽，没有"每种牌张数为 3 的倍数"这条约束。 《羊了个羊》正是靠把每种牌 ×3 存进总数组再洗牌，从结构上杜绝"消不完"； 但它不保证有解（解包分析：源码里没有求解/校验算法，第二关 28 层"许多关卡本身就是无解的"）。
三选一：甲 逆向构造（准备"3 张一组"的牌，每组放到当时最高层的空位； 反序消除即为一组解 ⇒ 100% 可解）← ✅ 第 31 轮采纳此案／ 乙 随机 + 校验重采样（game-4 口径：只保证"开局不卡"，中后段靠道具）（第 30 轮曾采此案，已升级）／ 丙 纯随机（对齐羊了个羊原版，允许无解）。
⚠ 本作比其他同类多一条「吃」（同花色连号三张），所以"一组 3 张"可以是 3 张同种，也可以是 1-2-3 连号。
A6 · 牌体占位口径：真母版要"填满画布"吗？（★ 本轮关键）
