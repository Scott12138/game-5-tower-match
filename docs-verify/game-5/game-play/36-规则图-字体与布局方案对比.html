三、落到小游戏里的字体口径（选型必须看这一栏）

HTML 原型里字体随便挑；但移植到微信小游戏后，字体只有两条路 —— 用系统字体，或把字体文件打进包。后者受主包体积硬约束，所以"选字体"实际是"定回退栈"。
做法体积代价表现可控性授权结论
正文/表格用系统字体
sans-serif		 0 KB iOS = PingFang SC；Android = 各家系统黑体。字形略有差异，但都是黑体、观感稳定 无风险（系统字体） 采用 —— 方案甲 / 丙的正文都走这条
标题内嵌宋体
（如思源宋体子集）		 中文全字库 8 MB+，必然超主包；只做"游 戏 规 则 / 弹层内十余个字"的子集可压到几十 KB 完全可控，两端一致 思源宋体 = SIL OFL，可商用内嵌；系统 Songti SC 不可内嵌分发 可选 —— 若要让标题气质跨端一致才需要；否则直接用 serif 回退即可
数字用等宽对齐
tabular-nums		 0 KB 「2 · 12」「×1」这类数值列位对齐，表格观感立刻整齐 无风险 采用 —— 三案都已生效
全域内嵌一套中文字体 8 MB 级，直接撞穿主包 4096 KB 上限 完全可控 取决于字库授权 不采用
一句话结论：正文与数字走系统无衬线 + tabular-nums；标题保留 serif 回退（真机 iOS 落宋体、Android 落系统衬线，可接受）。若哪天要求标题跨端绝对一致，再单独做一份"标题字子集"内嵌，代价只有几十 KB。
