第 3 条 · 已修

槽位显示错位 —— 找到真凶了

根因不是"第一个槽没渲染"，而是"每一次消除都会把后面所有槽位变成空壳"。 消除时先把槽内节点表清空，300 毫秒后再回头按它重排 —— 那时读到的已经是空表， 于是每一格都走了「只给尺寸、不给图片」的兜底分支，建出一批看不见的空壳节点。 数据是对的、外观是空的，所以你看到的现象正是「第一个槽里有牌却没显示出来」。

修法：存活节点在数据变更的同一步就被摘出来排队，重排时按序放回； 万一对不上，也强制补一张带图的，绝不填空壳。同一个毛病在 「消除道具」和「复活直消」两条路径上也各有一处，一并修掉。

复测证据 · 真实鼠标走「入槽 → 成组 → 消除 → 重排」： 修前 槽内数据 [3,4,6] 而三格 sprites:[] （一张图都没有） → 修后三格 spriteFrame: true
第 4 条 · 已验

四个道具都是好的 · 实测 7/7

用真实鼠标把四个道具逐个点了一遍（含"该失败时不许消耗"的反向用例）， 全部通过。所以「用了没成功」不是功能没实现，而是下面两种前置条件之一。

✅ 加槽 槽位上限 +1（8 → 9）
✅ 移出 槽内 −1 且牌回桌（桌上 11 → 12）
✅ 洗牌 桌面牌位真的重排了
✅ 消除 无组时不消耗道具、局面不变
✅ 消除 槽里真成组时能消掉（槽 3 → 0）
✅ 消除 生效时消耗 1 个（角标 1 → ＋）

「用了没成功」的两个真实原因： ① 这一关的四种道具本局数量是 0 —— 此时点格子不会生效，只会弹「看广告补 1 个」； ② 「消除」的前置条件是槽内已经凑成一组（三张同面／同花色连号）。 但自动判定会在牌入槽的那一刻就把成组的牌当场消掉，所以 正常玩下去你几乎永远碰不到「用消除」这个时机 —— 这不叫坏，叫用不上。 要不要给它换个更顺手的行为，你说了算。
