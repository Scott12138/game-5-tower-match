# 第 58 轮 · 主玩页桌外底色「明度 +20%」口径变更（sRGB → 线性）

> 用户 2026-10-07 拍板：明度口径取 **线性均值 ×1.20**（另一选项是"维持 sRGB 直接 ×1.20"）。
> 落地脚本：`game-5-cocos/tools/r42-bg-build.py` → `apply_gain()`。

## 一、两种口径到底差在哪（这是本次变更的**核心事实**）

| 口径 | 做法 | 编码值变化 | **物理亮度**变化 |
|---|---|---|---|
| 旧（第 42~57 轮） | sRGB 编码值直接 ×1.2 | 全局 +20% | 暗部 **×1.36** / 亮部 **×1.51** ⇒ 高光易爆白、对比被压 |
| 新（第 58 轮） | 线性光空间 ×1.2 再编码回 sRGB | 暗部 +11.6%（30→33.5）· 亮部 +8.5%（200→216.9） | **均匀 +20%** |

⚠️ 反直觉点：**新口径比旧口径暗**。因为"×1.2"在旧口径里被 sRGB 的非线性放大了
（编码值乘 1.2 ≠ 亮度乘 1.2）。所以这次变更是**把过度提亮修正回精确 +20%**。

## 三、回退口径（一行）

把 `tools/r42-bg-build.py` 的 `apply_gain()` 函数体换回：

```python
def apply_gain(v):
    return np.clip(v * GAIN, 0, 255)
```

然后重跑脚本 + 重新构建即可，其余全不用动。

## 四、本轮顺带修的脚本健壮性问题

候选原图 `CAND = /tmp/g5-r41-bg/B-page.png` 住在 `/tmp`（**会被系统清理**），
它缺失时脚本原先**直接 `SystemExit`** ⇒ `/tmp` 一被清就再也无法重出资产。

现已改为：**跳过「视觉参照 / 逐带对账」两段**（这两段只做人工对账，
**不参与资产生产** —— 资产来自重建稿 `b_cand`），并在产出清单里跳过缺失文件。

⚠️ **不要用重建稿当参照图替身**：两条纹样公式的尺度本来就不一样，
替身会产出一组"看着很准"的假对账数字。
